# 上篇 · 技术学习指南（面向 Java 背景）

## 0. 先说结论：你要学的其实只有一个东西

很多人以为选 Tauri 就要学 Rust。实际分工是：

| 层 | 语言 | 你要写的量 | 学习成本 |
|---|---|---|---|
| 界面、录入、查询、排程调用 | **TypeScript** | **95%** | 低（见 §1，你有 Java 底子，一两周够） |
| 数据库（SQL 写在哪） | SQL | 5% | 你会写 SQL 就没成本 |
| 外壳、窗口、插件注册 | Rust | **约 40–300 行，一次写完基本不动** | 中（但面积小到可以不学，抄模板） |

所以真实的学习路径是：**TypeScript → React → ts-fsrs → （可选）Tauri/Rust**。

**建议顺序**：不要一上来啃 Rust 书。先用 `create-tauri-app` 生成模板跑起来，然后在 TypeScript 里写业务，等真正需要改 `lib.rs` 时再查文档。**Rust 在你这项目里是一次性成本，不是日常语言。**

## 1. TypeScript 与 Java 的对照表（最重要的一节）

你已经会 Java，TS 的大部分概念都能直接映射。**只列出会误导你的差异**——这些是 Java 程序员最容易踩的坑。

### 1.1 直接对应

| Java | TypeScript | 备注 |
|---|---|---|
| `interface Foo {}` | `interface Foo {}` | 几乎一样。但 TS 的 interface 在运行时**不存在**，只是编译期检查 |
| `class Foo {}` | `class Foo {}` | 语法基本一样 |
| `List<String>` | `string[]` 或 `Array<string>` | 更常用 `T[]` |
| `Map<K,V>` | `Map<K,V>` | 一样，但 TS 的 `Map` 是 ES6 内置，不是集合框架 |
| `Optional<T>` | `T \| null` 或 `T \| undefined` | **没有 Optional 包装类**，直接用联合类型 |
| `enum Color { RED }` | `enum Color { RED }` | 有，但社区更爱用字符串字面量联合类型 |
| `String.format` | 模板字符串 `` `第 ${i} / ${n} 张` `` | **比 Java 好用得多** |
| `stream().filter().map()` | `arr.filter(x => ...).map(x => ...)` | 箭头函数 `=>` 代替 lambda |
| `throws Exception` | 无声明式检查 | **TS 不检查受检异常**，见 §1.3 |
| `public/private` | `public/private`（编译期） | 运行时都是公开的 |
| `Object` | `unknown`（推荐）或 `any`（禁用） | **`any` 会关掉类型检查，本项目禁止** |
| `@Override` | 无 | TS 用结构类型，不需要 |
| Maven `pom.xml` | `package.json` | |
| `javac` | `tsc` / Vite | Vite 会剥掉类型（不检查），所以**类型检查要单独跑 `pnpm typecheck`** |
| JUnit | Vitest | 语法几乎一样：`describe/it/expect` |
| Spring 的依赖注入 | 手写函数/repository 接口 | 不需要框架 |

### 1.2 会坑到你的五件事

**① 结构类型（structural typing）**

Java 是名义类型：`implements Foo` 才算 Foo。TS 是**结构类型**：只要长得一样就算。

```ts
interface Point { x: number; y: number }
const p = { x: 1, y: 2, extra: 3 }
const q: Point = p        // ✅ 合法，多出来的字段无所谓
```

好处是解耦，坏处是「看起来没关系的东西混进来也不报错」。**对策**：跨边界（IPC、导入 JSON）必须显式 `parse`，不要直接 `as`。

**② `undefined` 无处不在**

Java 只有一个 `null`。TS 有 `null` 和 `undefined` 两个，而且**访问不存在的对象属性返回 `undefined` 而不抛异常**。

```ts
const arr = [1, 2, 3]
arr[10]              // undefined，不是越界异常
```

所以项目里的 `tsconfig` 开了 `noUncheckedIndexedAccess`，**强制你在用数组元素前判空**。这不是洁癖，是防「下标越界静默变 `undefined` 然后炸在很远的地方」。

**③ 没有受检异常**

```java
void read() throws IOException   // Java 强制调用方处理
```
```ts
async function read(): Promise<string>   // TS 完全不知道会抛什么
```

**对策**：本项目所有数据库/AI 调用都包一层 `try/catch`，把错误转成返回值或抛出**自定义错误类**。不要指望编译器提醒。

**④ `this` 的绑定**

Java 里 `this` 永远是当前对象。JS 里函数单独传出去会丢 `this`。

**对策**：全项目用**箭头函数**和**独立函数**，不用类的方法做回调。这条规则能消掉 90% 的 `this` 问题。

**⑤ 异步：`Promise` ≈ `CompletableFuture`**

```java
CompletableFuture<String> f = CompletableFuture.supplyAsync(() -> "hi");
f.thenApply(s -> s + "!");
```
```ts
const f: Promise<string> = Promise.resolve('hi')
// 但日常直接 await：
const s = await f          // await 只能在 async 函数里用
```

| Java | TypeScript |
|---|---|
| `CompletableFuture<T>` | `Promise<T>` |
| `.thenApply()` | `.then()` / 直接 `await` |
| `try/finally` | `try/finally` |
| `Future.get()` 阻塞 | `await` |
| 线程池 | 事件循环（**单线程**） |

**关键差异**：JS 是单线程事件循环。**任何长计算都会卡住界面**。本项目里唯一的重计算是「解析 50 行文本」，可以接受；但如果你以后要处理十万词条，得考虑优化或丢进 Web Worker。

> **数据库调用一定要 `await`**。Tauri 的 SQL 插件是跨进程调用，返回 `Promise`。忘了 `await` 你会拿到一个永远不 resolve 的对象，然后「查询结果为空」——这是新人最常踩的坑。

### 1.3 类型体操：你只需要看懂的四个

**① 联合类型 `A | B`**

```ts
type Status = 'learning' | 'graduated' | 'suspended'
```
比 Java 的 enum 更轻。**本项目所有状态字段都用这个**，好处是拼错立刻报错，且直接映射成数据库里的字符串。

**② 字面量类型**

```ts
type Layer = 1 | 2           // 不是 number，只允许 1 或 2
type Origin = 'manual' | 'ai'
```

**③ 泛型**

```ts
function first<T>(arr: T[]): T | undefined { return arr[0] }
```
和 Java 一样，但**没有类型擦除问题干扰你**（运行时还是擦的，但 TS 允许在类型层面做很多 Java 做不到的事）。

**④ `Partial<T>` / `Pick<T, K>`**

```ts
type WordPatch = Partial<WordRow>     // 所有字段变可选
updateWord(id, { status: 'graduated' })   // 只传一个字段
```
Java 里你要为这个写一个单独的 DTO。TS 内置。

### 1.4 第一个能跑的 TS 例子（对照 Java 读）

```ts
// domain/normalize/headword.ts —— 这就是你项目里第一个真函数

export function normalizeHeadword(raw: string): string {
  return raw
    .trim()
    .toLowerCase()
    .replace(/\s+/g, ' ')          // 连续空白折叠成一个
    .replace(/^[^a-z0-9]+|[^a-z0-9]+$/g, '')   // 去首尾非字母数字
}
```

```java
// 等价的 Java
public static String normalizeHeadword(String raw) {
    return raw.trim()
              .toLowerCase()
              .replaceAll("\\s+", " ")
              .replaceAll("^[^a-z0-9]+|[^a-z0-9]+$", "");
}
```

**差别**：Java 写 `"\\s+"`（正则里反斜杠要转义），TS 的正则字面量 `/.../` 不需要。**TS 的函数是一等公民**，可以当参数传：

```ts
[3, 1, 2].sort((a, b) => a - b)      // 排序规则直接传
```

## 2. React：只学你项目需要的部分

React 的核心只有一句话：**界面是状态的函数**。你改数据，React 重新渲染；你**永远不直接操作 DOM**（不像 Swing 里 `label.setText()`）。

### 2.1 三个概念够用

**① 组件 = 返回 UI 的函数**

```tsx
function WordCard({ headword, meaning }: { headword: string; meaning: string }) {
  return (
    <div className="card">
      <div className="en">{headword}</div>
      <div className="cn">{meaning}</div>
    </div>
  )
}
```

`tsx` 就是「在 TS 里写类似 HTML 的东西」。`{headword}` 是插值，`className` 对应 Java 里给控件设样式。

**② `useState` = 局部状态**

```tsx
function ReviewPage() {
  const [index, setIndex] = useState(0)          // 等价于一个 int 字段 + setter
  const [revealed, setRevealed] = useState(false)

  return (
    <div onClick={() => setRevealed(true)}>
      <div>{words[index].headword}</div>
      {revealed && <div>{words[index].meaning}</div>}
      <button onClick={() => { setIndex(index + 1); setRevealed(false) }}>下一张</button>
    </div>
  )
}
```

**关键规则**：**永远不要直接改状态变量**。`index = 5` 是错的，必须 `setIndex(5)`。React 靠 setter 知道该重渲染。这条是新手第一大错。

**③ `useEffect` = 「在渲染之后做点什么」**

```tsx
useEffect(() => {
  repo.stats().then(setStats)     // 页面加载后查一次数据库
}, [])                            // [] 表示只执行一次
```

**它等价于**「页面初始化时」（Android 的 `onCreate`，Swing 的 `initComponents` 之后）。**不要滥用它**——很多初学者把所有逻辑塞进 `useEffect`，那是反模式。

### 2.2 你的项目里页面只有 5 个

```
pages/Home.tsx      首页（到期数 + 入口）
pages/Review.tsx    翻卡（核心）
pages/Import.tsx    粘贴录入 + 预览
pages/Search.tsx    查询 + 词条详情
pages/Settings.tsx  设置
```

**不需要学**：路由库（Tauri 单窗口，用一个 `useState<'home'|'review'|...>` 切页就够）、Redux、Context、SSR、Next.js。这些你项目里都用不上，别看那些教程。

## 3. ts-fsrs：这个库到底在算什么

### 3.1 一句话：它维护两个数，用它们算「下次什么时候见」

每个词有两个内部状态（这就是 FSRS 的全部记忆模型）：

| 字段 | 含义 | 直觉 |
|---|---|---|
| `stability`（S，稳定度） | 记忆保持率降到 90% 所需的天数 | **越大越牢**。S=10 意思是「10 天后还有 90% 概率记得」 |
| `difficulty`（D，难度） | 这个词对你有多难，1–10 | **越大越难**。难词间隔长得慢 |

**外加**：`state`（New/Learning/Review/Relearning）、`due`（何时到期）、`reps`（复习次数）、`lapses`（遗忘次数）。

历史数据里你还会看到 `elapsed_days`、`scheduled_days`、`learning_steps`、`last_review` —— 这些**在 v6 里已标记 deprecated**（v6.0.0 会移除），本项目仍然存它们是因为数据库表结构稳定、且日志需要记录。**你的业务代码不要依赖它们做逻辑判断**，只依赖 `stability`/`difficulty`/`state`/`due`。

### 3.2 一次结算做了什么

你给 `Good`，它做：

```
① 算回忆概率  R = forgetting_curve(now − last_review, S)
   你隔了 10 天，S 又是 5，那 R 就比较低

② 更新稳定度
   记住了（Good）→ 按「当前 R 有多低」决定涨多少
       R 低（隔久了还记得）→ 涨得多   ← 间隔被拉长
       R 高（刚复习完）    → 涨得少
   忘了（Again）→ 稳定度下降，按 forgetting_stability 公式重算

③ 更新难度
   Good 让 D 略降，Again 让 D 略升（有线性阻尼，不会突变）

④ 算下次间隔
   I = (r^(1/DECAY) − 1) / FACTOR × S      r = request_retention
   I 再被 maximum_interval 夹住
```

**关键点在这里**：**`elapsed_days` 是真实输入**。你不规律使用，隔了 20 天才复习，它知道；算出来的 `R` 低，它给的新间隔就不会盲目变长。

**这正是「自适应」对你不规律节奏有效的机制，也是它唯一比固定间隔强的地方。**

### 3.3 你只需要的四个 API

```ts
import { fsrs, generatorParameters, createEmptyCard, Rating, State, type Card } from 'ts-fsrs'

// ① 建实例（全局一个）
const f = fsrs(generatorParameters({
  request_retention: 0.85,
  maximum_interval: 50,
  enable_fuzz: false,
  enable_short_term: false,
  learning_steps: [],
  relearning_steps: [],
}))

// ② 新词 → 空卡 → 立刻记一次 Good（因为录入=今天已经背过了）
const fresh: Card = createEmptyCard(new Date())
const { card: first } = f.next(fresh, new Date(), Rating.Good)
// first.state === State.Review，first.due === 若干天后

// ③ 复习一次（next() 不修改入参，返回新对象，别忘了接住）
const { card: next } = f.next(currentCard, new Date(), Rating.Good)   // 或 Rating.Again

// ④ 还剩多少记忆（0–1），可用于显示「这个词你大概还记得 72%」
const r: number = f.get_retrievability(currentCard, new Date())
```

**注意 ③**：`f.next()` **不会修改 `currentCard`**（它是不可变的），返回新对象。这点和 Java 里「把这些 setter 调一遍」不同，别忘接住返回值。

### 3.4 为什么关掉 `enable_short_term`

默认是 `true`，会启用「学习步进」（`learning_steps: ['1m', '10m']`）：新卡先 1 分钟后再来，然后 10 分钟后再来。

**这个机制是给 Anki 那种「一天内反复清队列」的用法设计的。** 你的用法是**一次会话看完就走**，日粒度。开着它会导致：

- 刚录完的词，1 分钟后又被要求复习
- 一张卡在一次会话里反复出现，`reps` 被抬高，间隔计算失真

所以设 `enable_short_term: false` + 两个 `steps` 都设空数组。**这是本项目最重要的一条参数决策。**

### 3.5 为什么关掉 `enable_fuzz`

`enable_fuzz: true` 会给间隔加 ±5% 的随机抖动，防止所有词挤在同一天。对 Anki 那种几千词的大库有意义。

**对你没意义，反而有害**：同一个词、同样历史，算出来应该是同一个日期。加了随机，你测不了、也解释不了「为什么这次是 17 天上次是 18 天」。**关掉，保住可测试性。**

### 3.6 保留率 0.85 的实际含义

`request_retention` = 你希望复习时「还记得」的概率。

- `0.90`：记得牢，复习多。这是 FSRS 默认值、也是 Anki 常用值
- `0.85`：**本项目默认**。间隔约为 0.90 档的 1.9 倍，复习量约减半，代价是少数词会想不起来
- `0.80`：更省时间，忘得明显变多

公式是 `I = (r^(1/DECAY) − 1)/FACTOR × S`，其中 `FACTOR = e^(ln0.9/DECAY) − 1`，`DECAY = −0.1542`（FSRS-6）。

把保留率从 0.90 降到 0.85，**间隔约变成 1.9 倍，复习量约减半**：

| 目标保留率 | 间隔倍数 | 你复习时的感受 | 复习量 |
|---|---|---|---|
| 0.95 | 0.40 × | 几乎都认识，但复习排得很密 | 约 +150% |
| 0.90 | 1.00 × | 基本都认识，很顺 | 基准（FSRS 默认） |
| **0.85** | **1.91 ×** | 偶尔有一两个卡住 | **约 −48%（本项目默认）** |
| 0.80 | 3.32 × | 明显开始忘 | 约 −70% |

> 这张表按 FSRS-6 的 `DECAY = −0.1542` 计算，**已于 2026-10-27 用独立脚本复算核对过**。库版本升级后 `DECAY` 可能变（FSRS-5 是 −0.5，会得到完全不同的倍数），**升级后重跑开发文档 §5.2 里那段核对脚本**。

**代价提醒**：保留率调得越低，间隔越长，越多词会顶到 `maximum_interval`（本项目 50 天）。真要用 0.80，记得把最大间隔一起调大。

### 3.7 你必须知道的失败模式

**如果你每次都无脑点「背对了」，FSRS 收到的永远是 Good。**

后果：`stability` 只涨不跌，间隔一路拉长，最后所有词都被推到 `maximum_interval`（本项目 50 天）。此时它**退化成一张固定间隔表**，和固定间隔算法没有区别。

这不是 bug。**自适应的信息来源于你的反馈；没有反馈，它就只是「按经过天数调整的固定表」。** 你要清楚这一点：
- 每次都不看就点「背对了」→ 你就得到一张「按实际天数调整的间隔表」，够用
- 想真自适应 → 看到中文之后**老实判断**，卡住的就点「背错了」，不需要犹豫

两步流程（§7.2）就是为这个设计的：它先逼你把答案翻出来，评分只发生在你看过答案之后。

### 3.8 如果你以后想「重算全部历史」

`ts-fsrs` 有 `reschedule()`，靠 `FSRSHistory[]`（你的 `review_logs` 表能直接映射）重放历史，把每张卡重算到最新状态。**这就是为什么开发文档要求「即使不记对错也要记时间戳」**——没有日志，这个能力永远用不上。

## 4. Tauri：你只需要知道的那一点

### 4.1 它是什么

一个**把网页装进原生窗口**的外壳，和 Electron 同类，但用**系统自带的 WebView2**（Windows 上已预装）而不是打包整个 Chromium。所以产物 10 MB 而不是 150 MB。

```
你的 TS/React 代码  →  Vite 打包成 HTML/JS/CSS  →  塞进 WebView2
                                                      ↕ IPC
                                                    Rust 外壳
                                                      ↕
                                                    系统 API / 文件 / 托盘
```

### 4.2 你会碰到的配置文件只有三个

**`src-tauri/tauri.conf.json`** —— 窗口大小、标题、打包设置

```json
{
  "productName": "wordpacer",
  "identifier": "com.yourname.wordpacer",
  "app": {
    "windows": [
      { "title": "背单词", "width": 900, "height": 700, "resizable": true }
    ]
  },
  "bundle": {
    "active": true,
    "targets": ["nsis"],
    "icon": ["icons/32x32.png", "icons/128x128.png", "icons/icon.ico"],
    "windows": { "webviewInstallMode": { "type": "downloadBootstrapper" } }
  }
}
```

**`src-tauri/Cargo.toml`** —— Rust 依赖（抄模板即可）

**`src-tauri/capabilities/default.json`** —— 权限。**Tauri v2 的核心安全机制**：插件能力默认全关，必须显式授权。这是 v2 相对 v1 最大的变化，也最容易让人卡住。

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "sql:default",
    "sql:allow-load",
    "sql:allow-execute",
    "sql:allow-select",
    "dialog:allow-save",
    "dialog:allow-open",
    "fs:allow-write-text-file",
    "fs:allow-read-text-file"
  ]
}
```

> **最常见的错**：插件装了、Rust 注册了，但 TS 里调用报 `not allowed`。**99% 是 `capabilities` 里少了对应 permission。** 记住这个排查点能省你半天。

### 4.3 SQL 插件怎么用（这是你唯一的数据库入口）

```ts
import Database from '@tauri-apps/plugin-sql'

let db: Database | null = null

export async function getDb(): Promise<Database> {
  if (!db) db = await Database.load('sqlite:wordpacer.db')
  return db
}

// 查询
const rows = await getDb().then(d => d.select<WordRow[]>(
  'SELECT * FROM words WHERE status = ? AND fsrs_due_day <= ? ORDER BY fsrs_due_day LIMIT ?',
  ['learning', today, 150],
))

// 写入
await getDb().then(d => d.execute(
  'UPDATE words SET status = ? WHERE id = ?',
  ['graduated', 42],
))
```

**参数用 `?` 占位**（防 SQL 注入，也更快）。**不要字符串拼接**。

### 4.4 迁移（schema 演进）

在 `lib.rs` 里声明，插件启动时自动跑、自动记版本：

```rust
let migrations = vec![
    Migration {
        version: 1,
        description: "init",
        sql: include_str!("../migrations/0001_init.sql"),
        kind: MigrationKind::Up,
    },
];
```

**规则**：`0001_init.sql` 发版后**永不再改**。要改 schema 就加 `0002_xxx.sql` 并把 `version` 升到 2。这和你熟悉的 Flyway/Liquibase 是同一个思路，只是更轻。

## 7. 日常使用（三步循环）

### 7.1 打开软件

首页显示：

```
今日到期        87 张        [开始复习]
顺延中          12 张        [一次性看完]
词库            1,284 词 · 学习中 1,102 · 已毕业 182
下次到期最早     3 天后
```

- **今日到期**：现在该复习的总数。点「开始复习」
- **顺延中**：上次没排进来的，这次优先。**这个数字应该是逐次下降的**
- **下次到期最早**：如果显示「今天没有到期」之外的日期，说明你今天可以只录新词

### 7.2 复习

复习是**两步**，不是一步：

1. 一屏一张，**只显示英文**。先自己回忆意思
2. 点屏幕任意处（或按空格），或者直接点 **「我记到了」** → 中文淡入
3. 看到中文之后，才判断：
   - 意思对得上 → **「背对了」**（`Rating.Good`）
   - 想错了 / 忘了 → **「背错了」**（`Rating.Again`）

**顺序是乱的。** 每次打开，词是按「逾期最久优先」选出来的（这条不变，顺延的词照样不清零），
但这些词的**出场顺序会被打乱**——否则你连着看 150 张，记住的是「第 87 个是 abandon」这个位置，
而不是这个单词。打乱只影响先看哪张，不影响看哪些词。

想回看上一张：`←`。回看同一张不会重复记账（不会再给你算一次复习次数）。

**看到中文之后才评分**，这是重点。老版本是「点下一张 = 默认我会」，
你还没看到答案就已经默认记住了 —— 背错了也无从发现，算法收到的全是假的 Good。
现在没有任何路径能在你看到中文之前产生评分。

### 7.3 录入今天的词

点「录入」→ 在文本框里粘贴，每行一个：

```
abandon 放弃；抛弃
abstract 抽象的
accommodate	容纳
```

规则：

- **英文和中文之间**：空格、Tab、逗号都行
- **中文多个意思**：用 `；` `;` `，` `,` `/` 分隔 → 会拆成多条义项
- **只写英文**也行（释义以后补）
- **顺序不限**（英文在前）

点 **「解析预览」** → 检查这个摘要：

```
38 行 · 新增 35 · 追加义项 2 · 重复 1 · 错误 0
```

- **新增**：新词条
- **追加义项**：这个词已存在，新意思会加到它下面（**不会**覆盖旧的）
- **重复**：完全相同，忽略
- **错误**：这行没解析出英文，不会入库（会列出原文）

确认无误 → 点 **「导入」**。

> **录入即等于「今天背过了」**。系统会立刻按 FSRS 给它排第一个复习日期（实测 4 天后）。

#### 录完随时再看一遍

刚录完的词，当天想再翻一眼，不用等到下次复习。两个入口：

- **导入成功后**，录入页会多出一个按钮，点它直接进「今日新词」
- **首页**：录过词之后，首页会多一块 `再看一遍（今天录入 12 张）`。
  今天没录词时这块**不出现** —— 不给你一个点开是空的入口

卡片长得和复习页一样：只显示英文，点一下出中文。但**下面只有一个按钮** ——
「我记到了」翻出中文，再点「下一张」。它不判对错，也没有「背错了」。

> **翻看不影响任何东西。** 不写复习日志、不改下次到期日、不动首页的「今日到期」。
> 就是「再看一遍今天背的单词」，**不算一次复习**。
> 想让它真的推进排程，走首页的「开始复习」—— 那才是唯一会记一笔的地方。

## 8. 每个设置项到底在做什么

| 设置 | 默认 | 它真的在做什么 | 什么时候该改 |
|---|---|---|---|
| **目标保留率** | 0.85 | 你希望复习时还记得的概率。调低 → 间隔变长、复习变少、忘得变多。0.90 比 0.85 复习量多约 1/3 | 觉得忘太多 → 调到 0.88–0.90；觉得复习压身 → 0.82 |
| **单次会话上限** | 150 | 一次打开最多看多少张。**不改变到期计算**，只决定这次看多少，超出的顺延 | 每次觉得太长 → 调到 100；觉得顺延一直在涨 → 调到 200 |
| **最大间隔** | 50 天 | 单个词的复习间隔上限。到了就不再拉长。**为什么是 50 而不是 365：你的考试在明年 3 月，考前只剩约 140 天；排到 200 天后的词等于考前再也见不到** | 考完试想长期用 → 调到 365 |
| **毕业间隔** | 90 天 | 间隔到 90 天、**并且复习满 4 次**，才标「已毕业」。备考期内因为上限只有 50 天，够不到 90，所以**没有词会悄悄毕业** | 想保有量更高 → 调大；想把词赶紧清出去 → 调小 |
| **最少复习次数** | 4 次 | 防止「一次 Good 就算毕业」：没有这条，上限一夹，新词可能两次复习就被判定毕业 | 不建议低于 3 |
| **强制毕业阈值** | 6 次 | 一个词被标「背错了」累计 6 次，强制毕业，不再纠缠 | 有顽固词反复出现 → 调到 4 |
| **一天的边界** | 04:00 | 凌晨 2 点背的词算「昨天」。避免深夜学习被误判逾期 | 你常熬夜到 3 点后 → 调到 05:00 |
| **AI 校对** | 关 | 录入时检查英文拼写有没有写错。**只提示，不改你的录入，不生成释义**。关着完全不联网 | 录入常手滑、想有人盯一眼时开 |
| ~~AI 预算~~ | — | **未实现**。靠「默认关闭 + 只在点预览时请求」控成本，不做配额 | — |

### 8.1 什么时候该焦虑，什么时候不该

**不该焦虑**：

- 隔了一周没打开。**不会有惩罚，只有顺延**。下次打开它会先给你最危险的词
- 今天背了 10 个而不是 30 个。**没有配额，多少都行**

**该看一眼**：

- 「顺延中」连续几次在涨。这说明到期量长期大于你的复习速度。**动作**：把上限调大一点，或连续几天只复习不录新词
- 「下次到期最早」一直是「今天」。说明队列一直满着

## 9. 数据与备份

### 9.1 你的数据在哪

| 内容 | 位置 |
|---|---|
| 词库 + 学习记录 | `%APPDATA%\com.yourname.wordpacer\wordpacer.db`（单文件） |
| 自动备份 | 同目录 `backup\wordpacer-YYYYMMDD.db` |
| 手动导出 | 你自己选的位置，`.json` |

### 9.2 备份（**最重要的一件事**）

这个应用**没有服务器**。硬盘坏了、系统重装，数据就没了。所以：

- 首页会在距上次备份超过 7 天时提示
- **养成的习惯**：每周点一次「导出」，存到网盘或另一块盘
- 换电脑：旧机导出 → 新机安装 → 导入

### 9.3 导入的两种模式

| 模式 | 行为 | 何时用 |
|---|---|---|
| **合并（merge）** | 按单词合并，已存在的**以导入文件为准更新**，新的加入 | 从备份恢复；两台机器合并 |
| **替换（replace）** | **清空全部**再导入 | 完整恢复；确定要覆盖 |

> 替换模式会弹两次确认。**它不写备份**，先手动导出一次再操作。

### 9.4 导出格式

```json
{
  "version": 1,
  "exportedAt": "2026-10-27T16:00:00+08:00",
  "settings": { "request_retention": 0.85, "session_limit": 150 },
  "words": [
    {
      "headword": "abandon",
      "norm": "abandon",
      "status": "learning",
      "senses": [
        { "meaningCn": "放弃；抛弃", "layer": 1, "origin": "manual" }
      ],
      "fsrs": {
        "state": 2, "due": 1793000000000,
        "stability": 3.42, "difficulty": 4.81,
        "reps": 2, "lapses": 0, "scheduledDays": 3
      }
    }
  ]
}
```

**不含 API Key，不含复习日志**（日志体积大且不影响恢复）。导出时会自动剔除所有 `ai_` 开头的设置项，所以 Key 不会跟着备份文件跑出去。

**AI 校对用的 Key 存在哪？**
明文存在本机 `settings` 表里（`%APPDATA%\com.wordpacer.app\wordpacer.db`），和排程参数同一张表。它只在本机，不参与同步；导出时被剔除。如果你把这台电脑借给别人，记得在设置页把 Key 清掉。

## 10. 常见问题

**Q：为什么复习时只显示英文？**
这是刻意的。看到中文再回忆英文，是「再认」；看到英文自己回忆中文，是「回忆」。后者才建立记忆。点一下才给答案，是为了让你先真的想一下。

**Q：为什么我补的意思有时候不显示？**
事后补充的义项（L2）要等这个词复习满 3 次之后才出现在卡片上。否则它会提前泄露答案，让你下次回忆时把「刚看过的」当成「本来就会的」。它现在可以在词条详情页看到。

**Q：我隔了一个月没打开，会怎样？**
不会崩。它算出所有到期词，按逾期从久到近**选出**前 150 张，再把这一轮的**出场顺序打乱**。剩下的顺延到下次，优先处理。**「顺延中」这个数字在下降，就说明你在恢复节奏。**

**Q：顺序是乱的，会不会有词永远轮不到？**
不会。打乱只作用于「这一轮先看哪张」，**选哪些词仍然是逾期最久优先**。所以状态差的词照样优先进来，只是进来之后的先后随机。

**Q：为什么它有 200 张到期，只给我 150 张？**
这是「会话上限」，防止你一次面对 400 张然后关掉软件。可以在设置里改，也可以用首页的「一次性看完」临时突破。

**Q：是不是不点「背错了」就等于没用自适应？**
基本是。没点「背错了」，算法收到的就全是 Good，只会按「实际过去了多少天」调整间隔——这仍然比固定间隔好（它知道你隔了多久），但不包含「这个词你记不住」的信息。想让它真自适应，就在看到中文之后老实判断，卡住的点一下，不用每张都犹豫。

**Q：同一个词的 `abandoned` 会被合并进 `abandon` 吗？**
不会。**故意不做词形还原**。你背的是哪个词形，就存哪个。但录入时会提示「可能重复：abandon（已存在）」，由你决定。

**Q：能装在手机上吗？**
v1 不能，这是只装在自己 Windows 电脑上的桌面应用，没有手机端。

**Q：能多台电脑同步吗？**
不能。最小方案是「导出 JSON → 拷过去 → 合并导入」，手动做。

**Q：会不会上传我的数据？**
不会主动上传。**没有任何遥测、没有后台网络请求**。

唯一的出网口是 AI 校对（默认关闭）：你开启并在录入页点「解析预览」时，才会把**这批词的英文**（不含中文释义、不含复习记录、不含历史）发给 AI 服务商。词库和复习记录永远只在本地。

**Q：双击没反应 / 白屏？**
1. 确认 WebView2 已安装（Win10 1803 以上/HPL 通常自带；没有就装一次 Microsoft Edge WebView2 Runtime）
2. 看 `%APPDATA%\com.yourname.wordpacer\logs\` 有没有错误日志
3. 通常是数据库迁移失败。**不要删库**，先备份 `wordpacer.db` 再排查

## 11. 术语表（给看代码时的自己）

| 词 | 含义 |
