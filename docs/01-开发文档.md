## 2. 产品定位

### 2.1 它是什么

一个**排程器**。它不教你单词，不考你，不评判你。它只做三件事：

1. 记住你背过哪些词、每个词的释义
2. 每次你打开它，算出「现在最该看哪些词」
3. 把词一张一张翻给你看

### 2.2 它不是什么（明确不做，写进代码注释也行）

| 不做 | 原因 |
|---|---|
| 不是测验工具 | 不判对错、不打分、不出选择题 |
| 不做连续打卡 / streak | 你一断就再也不想打开，打卡是劝退机制 |
| 不做每日配额 | 「今天必须背 30 个」在你不背的那天会变成负债 |
| 不做日历网格主界面 | 满屏空格制造负罪感 |
| 不做考试/成绩预测 | 不推算覆盖率、不预测分数；只显示「到期 / 顺延 / 词库总数」 |
| **不做内置核心词表** | 词库完全由你自己录入。**不预置 1500 核心词、不做词表分层、不做「覆盖率 / 预计完成日」推算**（用户明确 v1 不要）。`source` 字段只作标签，不参与任何计算 |
| 不做云同步、账号 | 纯本地，数据是你的 |
| 不做桌宠 | v1 砍掉；接口位置不留 |
| AI 不参与回忆屏 | AI 只在背完之后跑，见 §4.7 |

### 2.3 用户与节奏模型（决定一切参数）

- 单人使用，就是作者本人
- **每次录入 30 个词左右甚至更多**，但**不规律**——可能昨天 10 个，今天不背，明天 40 个
- 考试目标：**专升本**（约明年 3 月），四六级为次要
- 复习动作是**扫读**，不是逐词测试

> 关键推论：**系统里不存在「每天」这个概念。** 只有「这次打开」。所有以天为单位的机制（配额、打卡、日历）必须删掉。

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 词条（word） | 一个单词，含若干义项，含一份 FSRS 记忆状态 |
| 义项（sense） | 一条中文释义。L1 = 当初录入的；L2 = 事后补充的（含 AI） |
| 归一化键（norm） | 小写、去首尾空白、去标点、折叠内部空格后的字符串，用于去重与查询 |
| 卡片（card） | 复习时的显示单位，一张卡 = 一个词条 |
| 会话（session） | 一次「打开软件 → 复习 → 录入 → 关闭」的过程 |
| 到期（due） | `fsrs_due_day <= 今天` 的词条 |
| 顺延（deferred） | 到期但被会话上限挡住、留到下次优先处理的词条 |
| 毕业（graduated） | 间隔足够长、不再排入复习的词条 |

## 4. 功能规格

### 4.1 录入（最高优先级——这是唯一会让你放弃的环节）

**必须**支持行式批量录入。你把今天背的词一次贴进来，而不是一个一个弹窗。

输入格式（按行解析，容错）：

```
abandon 放弃；抛弃
abandon	v. 放弃
abandon
```

解析规则：

1. 每行一条。取**第一个连续的 ASCII 字母序列（允许 `-`、`'`、空格，如 `used to`）**作为英文，其余部分作为中文释义
2. 英文缺失 → 该行标记为**错误行**，整行不落库，界面列出错误行号与原文
3. 中文为空 → **允许落库**（先建卡，释义后补），但需在结果里提示「N 条无释义」
4. 中文里若含 `；`/`;`/`，`/`,`/`/`，按分隔符拆成**多个 L1 义项**
5. 去重：`norm` 已存在 → **不新建词条**，转入「追加义项」流程（见 4.1.2），并在结果里提示「已存在，最后复习于 X」

#### 4.1.1 归一化

`norm(headword) = lower(trim(headword))`，然后：

- 折叠连续空白为单空格
- 去首尾非字母数字字符
- **不做词形还原**（`abandoned` 和 `abandon` 是两张不同的卡）——见 §4.1.3 的理由

#### 4.1.2 追加义项（这是用户明确的需求）

- 已有词条被再次录入时，进入「追加」而非「新建」
- 追加的义项标 `layer = 2`、`origin = manual | ai`
- **L2 义项默认不在首次回忆屏出现**（防止事后补的意思提前泄题，见 §4.3.3）

#### 4.1.3 为什么不做自动词形还原

本项目**主动不做**词形归并，原因：

- 你录入的是**你正在背的那个词形**。把 `abandoning` 悄悄并入 `abandon`，会让「我今天背的是哪个词」这件事失真
- 自动归并出错时你很难发现，而错误会永久留在排程里

**代替方案**：录入时若 `norm` 与某个已存在词条**编辑距离 ≤ 1 且词根相同**（去掉 `-s/-ed/-ing/-ly` 后相等），提示「可能重复：`abandon`（已存在）」，由你决定合并还是新建。**提示，不自动改。**

### 4.2 查询

**必须**支持：

- 按英文查（前缀匹配 + 完全匹配），大小写不敏感
- 按中文释义查（`LIKE '%关键词%'`）
- 结果行显示：`headword · 首条 L1 释义 · 状态（学习中/已毕业/已暂停）· 最后复习日期 · 下次到期日`
- **「背过没有」**：查不到 = 没背过；查到 = 背过，且直接看到最后复习日期

**应**支持：筛选「只看已毕业」「只看今天到期」。

### 4.3 复习会话（产品心脏）

#### 4.3.1 进入

打开应用 → 首页 → 一个按钮「开始复习（今日 87）」。数字 = 当前到期的词条总数。

#### 4.3.2 卡片形态（用户明确要求）

- 一屏一张卡，**只显示英文**
- 点一下（或按空格）→ 中文淡入
- 左滑 / ← → 上一张；右滑 / → → 下一张
- **默认动作 = 记住**。看完即算完成，不点任何按钮也会推进
- 底部可选按钮：**「不会」**（默认关闭，需在设置里开启）。开启后按它 → `Rating.Again`；不按 → `Rating.Good`
- 顶部始终显示：`第 i / N 张`、`逾期最久 X 天`

> 不显示进度条动画、不显示连击、不显示「你已连续 3 天」。只有一个 `i / N`，因为它只提供位置信息，不提供情绪。

#### 4.3.3 义项显示规则

| 层 | 首次回忆屏（点一下之前） | 点一下之后 |
|---|---|---|
| L1 | **不显示**（这是要你回忆的东西） | 显示 |
| L2 | 不显示 | 显示，但**带「补充」角标**，且**排在同词第 3 次复习之后才出现** |

L2 的出现时机由 `fsrs_reps >= 3` 控制。理由：如果 L2 一上来就跟着显示，你下次回忆时会把它当成「我本来就会的」。

#### 4.3.4 会话上限与顺延

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `session_limit` | **150** | 60–300 | 单次会话最多排入多少张卡 |

规则：

1. 取所有 `status = 'learning'` 且 `fsrs_due_day <= 今天` 的词条
2. 按 `fsrs_due_day ASC`（逾期最久优先）→ `fsrs_stability ASC`（越不牢越优先）→ `id ASC` 排序
3. 取前 `session_limit` 条排入本次会话
4. 其余**不消失、不清零**，留在队列里，下次打开时天然排在最前（因为它们逾期更久）
5. 界面显示三元组：`排队 X / 本次 Y / 顺延 Z`
6. 提供「一次性看完」按钮：临时忽略上限，把 Z 也排进来

> **这是「节奏不乱」的技术定义**：你永远不需要「补完」，只需要每次还一点，且系统保证还的永远是最危险的。**顺延数 Z 逐次下降 = 节奏在恢复；Z 持续上涨 = 该调小上限或该背新词了。**

#### 4.3.5 会话结束

- 每张卡完成时立即写 `review_logs` 并更新词条的 FSRS 状态（逐卡提交，不是整批提交——中途关掉软件不丢数据）
- 会话结束后显示：`本次 N 张 · 标记不会 M 张 · 下次到期 明天 / 3 天后`
- **不做「复习完成」庆祝弹窗**

### 4.4 首页

只有一个屏，四块信息，都不带情绪装饰：

```
今日到期        87 张        [开始复习]
顺延中          12 张        [一次性看完]
词库            1,284 词 · 学习中 1,279 · 已毕业 5
下次到期最早     3 天后
```

> **注意「已毕业」在备考期内几乎不动**：`maximum_interval=50 < graduate_interval=90`，间隔永远够不到毕业线，所以「学习中」会占绝大多数，而「已毕业」这个数字只会因为 `graduation_on_lapses`（顽固词强制毕业）缓慢增加。**这是设计使然（§5.6.1），不是 bug。** 不要为了让这个数字好看去调小 `graduate_interval`——那等于让词在你忘掉之前就消失。

外加两个入口：**录入**、**查询**。

### 4.5 设置

| 项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `request_retention` | 0.85 | 0.80–0.95 | 目标保留率。越低复习越少、忘得越多 |
| `session_limit` | 150 | 60–300 | 单次会话上限 |
| `maximum_interval` | **50** | 20–3650 | FSRS 间隔上限（天）。**考试导向的硬约束，数字是倒推出来的，见 §5.6.1** |
| `graduate_interval` | **90** | 30–365 | 间隔达到此值、**且次数达标**才毕业（天）。备考期内 > `maximum_interval`，故不会触发 |
| `min_reps_to_graduate` | **4** | 2–10 | 最少复习次数，防止「间隔一长就毕业」 |
| `graduation_on_lapses` | 6 | 3–20 | 遗忘次数达到此值强制毕业 |
| `enable_again_button` | false | — | 是否显示「不会」按钮 |
| `day_boundary_hour` | 4 | 0–6 | 一天的边界小时，见 §6.2 |
| `ai_enabled` | false | — | AI 校对总开关 |
| `ai_api_key` | — | — | 明文存本机 `settings` 表，导出时整体剔除（见 §12.3） |
| `ai_base_url` / `ai_model` | DeepSeek 默认 | — | 可换端点（OpenAI 兼容） |

### 4.6 导出 / 导入（**必须，属于 MVP**）

单机无服务 = 硬盘坏、系统重装就全丢。这是唯一的数据保险。

- **导出**：一个 `.json` 文件（可选 `CSV`：`headword,meanings,status,due_day,reps,lapses`）
- 导出内容：全部词条 + 全部义项 + 全部设置（**不含 API Key**）
- **导入**：两种模式 —— `merge`（按 `norm` 合并，冲突以「更新」为准）/ `replace`（清空后导入）
- 导出前先执行 `PRAGMA wal_checkpoint(TRUNCATE)`，确保拿到一致快照（见 §8.4）
- **应**：每次启动时若距上次备份 > 7 天，首页显示一行「距上次备份 9 天 · 导出」

### 4.7 AI 旁路（默认关闭）

**边界（硬约束）**：AI **绝不进入回忆屏**，绝不生成「给你背的中文释义」。

#### 4.7.1 已实现：录入校对（M6 第一项）

用户在**录入**时，AI 只当**校对员**，检查英文侧有没有写错。

| 项 | 定稿 |
|---|---|
| 触发 | 点「解析预览」后**自动**跑一次；改完内容再点一次就重新校对 |
| 检查内容 | 拼写错误 / 词形不对 / 查无此词 |
| **不检查** | 中英是否对得上、中文错别字、释义格式 —— 误报率高，第二期再议 |
| **不发** | 中文释义一个字节都不发，只发 `行号\t英文` |
| **不改** | 只提示。不自动改任何一行，不生成任何释义 |
| 结果呈现 | 预览面板「AI 认为这些行可能有拼写问题」区块 + 逐行明细行内标注 |
| 失败 | 静默降级：显示一行原因（超时 / Key 无效 / 余额不足），**不阻塞导入** |
| 关闭时 | 完全无痕：不显示任何 AI 字样，也不发任何请求 |

工程实现：

- 纯逻辑在 `src/domain/ai/`（`types` / `prompt` / `parse` / `config` / `apply`），零 IO、可单测
- IO 在 `src/data/ai/client.ts`，走 `@tauri-apps/plugin-http` 绕开 WebView 同源策略
- 送检批大小 `CHUNK_SIZE = 40`，超出自动切批；单批失败不影响其它批
- 模型返回**一律当不可信输入**：剥 markdown 围栏、手写 parse、
  **丢弃本次没送检的行号**（防模型幻觉出 `line: 999`）
- 建议与原词相同则丢弃建议，避免 UI 出现「改成一样的」

#### 4.7.2 未实现：补义项 / 例句 / 辨析

## 5. 排程算法规格

### 5.1 选型：`ts-fsrs`，不自己实现

`ts-fsrs` 是 `open-spaced-repetition` 组织的官方 TS 实现，MIT 许可，v5.4.2 实现 FSRS-6。

**为什么是 FSRS 而不是固定间隔**：

- 固定间隔（1/3/7/15 天）遇到逾期只有一种反应：再等这么多天。**对你这种不规律使用的人，它会把间隔越拉越离谱**
- FSRS 的核心输入是「**实际过去了多少天**」，它会先算出这个时刻你还记得的概率，再决定下次间隔。**不规律不是它的弱项，是它唯一比固定间隔强的地方**
- 而且它**不需要模型、不需要 GPU、不需要联网**。它是几十行数学公式，不是「AI」

### 5.2 参数（v1 定稿）

```ts
import { fsrs, generatorParameters, createEmptyCard, Rating, State } from 'ts-fsrs'

const params = generatorParameters({
  request_retention: 0.85,   // 目标保留率
  maximum_interval: 50,      // 间隔上限（天）—— 不是 365，理由见 §5.6.1
  enable_fuzz: false,        // 关闭随机抖动：同状态必须给出同一结果，便于测试与预期
  enable_short_term: false,  // 关掉分钟级学习步进
  learning_steps: [],
  relearning_steps: [],
})
const f = fsrs(params)
```

**为什么 `enable_short_term: false`**：本应用是**日粒度**的——你不会一天打开十次来清分钟级队列。关掉后，`learning_steps` 不生效，所有间隔直接由 FSRS 记忆状态算成「天」。否则新卡会在 `Learning` 状态里以 1 分钟 / 10 分钟的间隔反复出现，与「一次会话看完就走」的形态冲突。

**保留率 0.85 vs 0.90 的量化差别**：FSRS 的间隔公式是（对应库内 `calculate_interval_modifier`）

```
I = (r^(1/DECAY) − 1) / FACTOR × S ,   FACTOR = e^(ln0.9 / DECAY) − 1 ,  DECAY = −0.1542（FSRS-6）
```

以 `r = 0.90` 为基准（此时修饰子恰为 1.00），间隔倍数如下（**已复算核对**）：

| `request_retention` | 间隔倍数 | 复习量变化 |
|---|---|---|
| 0.95 | 0.4026 × | 约 +150% |
| 0.90 | 1.0000 × | 基准 |
| **0.85** | **1.9064 ×** | **约 −48%** |
| 0.80 | 3.3160 × | 约 −70% |

> `DECAY` 随库版本变（FSRS-5 是 `−0.5`，FSRS-6 是 `−0.1542`），上表按 FSRS-6。**改参数后重跑下面这段核对**，别把数字当常数抄死：
>
> ```ts
> import { fsrs, generatorParameters, createEmptyCard, Rating } from 'ts-fsrs'
>
> for (const r of [0.95, 0.9, 0.85, 0.8]) {
>   const f = fsrs(generatorParameters({ request_retention: r, enable_short_term: false }))
>   // 关键：每次复习的时刻必须等于「上次算出的到期时刻」，否则测的不是真实间隔
>   let card = createEmptyCard(new Date('2026-01-01T04:00:00+08:00'))
>   let now = new Date('2026-01-01T04:00:00+08:00')
>   const ivls: number[] = []
>   for (let i = 0; i < 5; i++) {
>     card = f.next(card, now, Rating.Good).card
>     now = card.due
>     ivls.push(card.scheduled_days)
>   }
>   console.log(r, ivls)   // 0.85 → [4, 31, 173, 772, 2852]（不设上限时）
> }
> ```

默认 0.85：**复习量几乎减半**，代价是少数词会想不起来。这是「节奏管理器」而不是「备考冲刺器」该选的档位。

> **副作用提醒**：`request_retention` 越低，间隔越长，撞上 `maximum_interval`（本项目 50 天）的词越多，即「自适应」被削平得越早。0.80 档下第 2 次 Good 就会顶到上限。备考期就用 0.85；**考完试后**若想真正发挥 FSRS 的长间隔能力，再把保留率降到 0.80 并把 `maximum_interval` 调大。

### 5.3 评分映射（二元）

| 你的动作 | Rating | 说明 |
|---|---|---|
| 默认（看完即过） | `Rating.Good = 3` | 绝大多数卡片 |
| 点「不会」（开关开启时） | `Rating.Again = 1` | 少数卡片 |

**不使用 `Hard` / `Easy`**。理由：三档以上评分要求你每次做判断，250 张卡就是 250 次决策，三天后你会放弃。二元是「自适应」在成本上唯一可行的形态。

> **必须写进文档的失败模式**：如果你从不按「不会」，FSRS 收到的全是 Good，间隔会一路拉长，**最终退化成一张很长的固定间隔表**。这不坏，但你要知道「自适应」此时并没有在替你做事——它是被你的行为激活的，不是装上就变聪明。

### 5.4 到期判定（不做手工逾期分档——设计修正）

**v1 早期草案曾设计「逾期 ≤2 天正常 / 3–7 天不进阶 / >7 天回退一档」。定稿放弃，原因如下：**

FSRS 的间隔增长依赖 `retrievability`（回忆概率）。你隔了 10 天才复习同一个词，`elapsed_days` 更大 → `R` 更低 → `next_recall_stability` 给出的新稳定度增长更小 → **下次间隔自然更短**。

也就是说，**「逾期就少走一步」这件事 FSRS 已经在做，而且做得比手写分档精确**。再叠一层手工分档会造成两个机制互相打架（例如被手工回退又刚被 FSRS 拉长），结果不可解释、无法测试。

因此 v1 只有三条规则：

1. **到期判定**：`status = 'learning' AND fsrs_due_day <= 今天`
2. **排序**：`fsrs_due_day ASC, fsrs_stability ASC, id ASC`
3. **上限**：`session_limit`，超出顺延（§4.3.4）

「逾期越久越危险、越先处理」由排序第 1 项保证，这就是「节奏不崩」的全部实现。

### 5.5 新词入库即计一次 Good

你录入的词 = **今天已经背过了**。所以：

```ts
const card = createEmptyCard(now)                       // State.New
const { card: next } = f.next(card, now, Rating.Good)   // → State.Review，due = now + I₁
```

把它落库。**不要让新词当天再排进复习队列**，否则你会刚录完就又被要求看一遍。

### 5.6 毕业与强制毕业

**先修一个容易写错的判定**：不能只看 `scheduled_days >= graduate_interval`。因为 `maximum_interval` 会把间隔夹在上限上，**一个刚背第 2 次的新词，一次 Good 就能算出 31 天；如果再被夹到 `graduate_interval` 附近，它会被立刻「毕业」，从此再不出现**。这是最典型的「毕业判定写错」事故。

因此毕业必须**两个条件同时满足**：

```ts
const graduated =
  card.state === State.Review &&
  card.scheduled_days >= cfg.graduateInterval &&   // 间隔够长
  card.reps >= cfg.minRepsToGraduate               // 且确实复习过足够多次
```

| # | 条件 | 默认 | 含义 |
|---|---|---|---|
| 1 | 自然毕业 | `state=Review && scheduled_days >= 90 && reps >= 4` | 间隔拉到 90 天且至少复习过 4 次 |
| 2 | 强制毕业 | `lapses >= 6` | 怎么都记不住，认了，不再纠缠 |

**为什么必须有强制毕业**：如果某个词你怎么都记不住，没有上限的话它会永久循环、永久占用队列、永久拉高你的逾期数。设上限后，它变成「我认了，这个词就是记不住」，比你被它拖着好。

> 毕业不等于删除。它仍在词库里，查询得到，可一键重新激活（重置为 `State.New` + 立即排入下次会话）。

#### 5.6.1 为什么 `maximum_interval` 是 50 —— 这个数字是倒推出来的

这是**考试导向**的硬约束，不是技术偏好。

**先摆事实。** 用 `request_retention = 0.85`（`interval_modifier = (0.85^(1/−0.1542) − 1) / 0.9803 = 1.9064`）和 FSRS-6 默认权重计算，一个 New 卡连续给 `Good`、**不设任何上限**时的真实间隔：

| 第几次复习 | `stability` | 间隔 | 累计到第几天 |
|---|---|---|---|
| 1（入库） | 2.31 | **4 天** | 4 |
| 2 | 16.18 | **31 天** | 35 |
| 3 | 90.94 | **173 天** | 208 |
| 4 | 404.82 | **772 天** | 980 |
| 5 | 1496.05 | **2852 天** | 3832 |

> **这组数字已于 2026-10-27 用独立复算脚本核对过**（按 `next_recall_stability`、`mean_reversion`、`forgetting_curve` 原始公式手写实现，不依赖 `ts-fsrs`）。校验链：
>
> - `S₁ = w[2] = 2.3065` → `round(2.3065 × 1.9064) = 4` ✓
> - `D₁ = w[4] − e^(2·w[5]) + 1 = 6.4133 − 5.2953 + 1 = 2.118`
> - 第 2 次：`R = (1 + 0.9803 × 4 / 2.3065)^(−0.1542) = 0.858` → `S₂ = 16.18`
>
> **M0 仍要跑一遍 §5.2 的脚本核对**——万一库的行为与公式实现不一致，宁可在这里发现。

**结论：第 3 次复习就排到 173 天后，第 4 次 772 天。** 你今天录入的词，到考试时只见过 2 次，第 3 次排在你考完之后。

**再摆目标。** 今天（2026-10-27）到明年 3 月中旬约 **140 天**。要让每个词在考前至少见 **5 次**：

```
35 + 2M ≤ 140   ⇒   M ≤ 52
```

（前两次在第 0 天和第 4 天，第 3 次在第 35 天，之后每 M 天一次。）

取 **`maximum_interval = M = 50`**：

| 第几次 | 第几天 |
|---|---|
| 1 | 0（入库） |
| 2 | 4 |
| 3 | 35 |
| 4 | 85 |
| 5 | 135 ← 刚好在考前 |

**如果按常见默认值 365**：第 3 次复习排到 173 天后（还在上限之内），第 4 次被夹到 365 天。**你 3 月上考场时，绝大多数词只复习过 2 次，第 3 次排在你考完之后。** 首页的「已毕业」数字会很漂亮，但和你的实际记忆无关。

**配套决定：备考期内几乎没有词会毕业。** `graduate_interval = 90 > maximum_interval = 50`，间隔永远够不到 90，所以 `scheduled_days >= 90` 永不成立——**没有任何词会在备考期内悄悄消失**，它们每 50 天循环一次直到考试。（「已毕业」计数因此接近 0，只有强制毕业的顽固词会使它非 0。这是预期行为，不是 bug。）

考完试后想让词退休：把 `maximum_interval` 调回 365、`graduate_interval` 保持 90 即可，都是设置项，不改代码。

> **副作用（必须知道）**：`maximum_interval = 50` 意味着大量词的间隔被固定成 50 天，「自适应」在这里让位于「保证考前再见一次」。对 5 个月的备考期，精确区分 50 天和 200 天没有意义，**保证每个词在考前都还认得才有意义**。这是刻意的取舍。

### 5.7 会话生成伪代码（`domain/scheduler/session.ts`）

```ts
export function buildSession(
  candidates: WordRow[],      // 已按 §5.4 排序好的到期词条
  limit: number,
  includeAll = false,
): { picked: WordRow[]; deferred: number } {
  const n = includeAll ? candidates.length : Math.min(limit, candidates.length)
  return { picked: candidates.slice(0, n), deferred: candidates.length - n }
}
```

**这条函数必须是纯函数**：输入数组、输出数组，不碰数据库、不碰 `Date.now()`、不碰 `window`。时间从参数传进来。

### 5.8 单卡结算伪代码（`domain/scheduler/review.ts`）

```ts
export function settle(
  word: WordRow,
  rating: Rating,
  now: Date,
  cfg: SchedulerConfig,
): { card: Card; log: ReviewLog; graduated: boolean } {
  const prev = toCard(word)                       // 从行还原成 ts-fsrs 的 Card
  const { card, log } = cfg.fsrs.next(prev, now, rating)

  const graduated =
    (card.state === State.Review &&
      card.scheduled_days >= cfg.graduateInterval &&
      card.reps >= cfg.minRepsToGraduate) ||
    card.lapses >= cfg.graduationOnLapses

  return { card, log, graduated }
}
```

**`toCard` / `fromCard` 是唯一允许碰 FSRS 字段的地方**（`domain/scheduler/card.ts`）：

```ts
export function toCard(w: WordRow): Card {
  return {
    due: new Date(w.fsrs_due ?? Date.now()),
    stability: w.fsrs_stability,
    difficulty: w.fsrs_difficulty,
    elapsed_days: 0,                             // deprecated：库里不存，由库自己按 last_review 重算
    scheduled_days: w.fsrs_scheduled_days,
    learning_steps: 0,
    reps: w.fsrs_reps,
    lapses: w.fsrs_lapses,
    state: w.fsrs_state as State,
    last_review: w.fsrs_last_review ? new Date(w.fsrs_last_review) : undefined,
  }
}
```

> **两个 `0` 的理由**：`elapsed_days` 和 `learning_steps` 在 v6 都已标记 deprecated（v6.0.0 移除）。`ts-fsrs` 每次 `next()` 都会用 `last_review` 自己算出 `elapsed_days`，传 0 不影响结果；`learning_steps` 在 `enable_short_term: false` 时完全不参与计算。**所以数据库里不用为它们建列**——少两列，少一类「存了但没人读」的僵尸数据。日志里仍然记录它们（由 `log` 对象带回），因为那是审计信息。

### 5.9 边界情况（必须处理）

| 情况 | 处理 |
|---|---|
| **系统时间回拨** | `now < last_review` 时，`elapsed_days` 夹到 0，并在日志记一条 `clock_back` 警告，不推进 |
| **同一天重复复习同词** | 正常允许（`elapsed = 0`），但 UI 上该词当天不再自动出现 |
| **跨天边界** | 见 §6.2，用 `day_boundary_hour` 而非 00:00 |
| **某词 `stability` 为 0 但状态是 Review** | 视为损坏数据，重置为 `State.New`（迁移或修复脚本里处理） |
| **队列为空** | 显示「今天没有到期。」**不加任何催促文案** |
| **一次会话中途关闭** | 已结算的卡已落库，未结算的保持原状，下次重新排 |

## 6. 日期与时间

### 6.1 存储

- `fsrs_due`：`INTEGER`，epoch 毫秒（UTC）—— 交给 `ts-fsrs` 的 `Date`
- `fsrs_due_day`：`TEXT`，`YYYY-MM-DD` —— 应用算出的「日粒度键」，**仅用于索引与排序**
- `fsrs_last_review`：`INTEGER`，epoch 毫秒

> 为什么两个都存：`ts-fsrs` 需要 `Date`，而 SQLite 里按日期范围查询用字符串最快。两者由同一处代码（`domain/time.ts`）生成，不允许别处自己 `toISOString()`。

### 6.2 一天的边界 = 04:00（默认）

```ts
export function dayKey(now: Date, boundaryHour = 4): string {
  const d = new Date(now.getTime() - boundaryHour * 3600_000)
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}`
}
```

理由：你在 00:30 背的单词，心理上属于「昨晚」。用 00:00 分界会让深夜学习的人觉得刚复习完就逾期了。

### 6.3 时区

应用**只服务单机单时区**。所有日期换算走本地时区（`new Date()` 的本地方法），**不引入 `dayjs`/`luxon`**。中国无夏令时，不处理 DST。

### 7.3 Rust 侧到底写什么

只做三件事，其余全在 TS：

```rust
// src-tauri/src/lib.rs（示意，约 40 行）
use tauri_plugin_sql::{Migration, MigrationKind};

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    let migrations = vec![Migration {
        version: 1,
        description: "init",
        sql: include_str!("../migrations/0001_init.sql"),
        kind: MigrationKind::Up,
    }];

    tauri::Builder::default()
        .plugin(
            tauri_plugin_sql::Builder::default()
                .add_migrations("sqlite:wordpacer.db", migrations)
                .build(),
        )
        .plugin(tauri_plugin_dialog::init())
        .plugin(tauri_plugin_fs::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

1. 注册 `tauri-plugin-sql`（含迁移）
2. 注册 `dialog` / `fs` 插件（导出、导入）
3. 启动窗口

**不写任何 `#[tauri::command]`**。所有业务经 SQL 插件与 TS 完成。这是本项目能把 Rust 面积压到最小的关键决策。

### 7.5 数据库访问方式的选择

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **`@tauri-apps/plugin-sql`** | 官方、带迁移、Rust 侧零代码、SQL 直接可读 | 每次调用跨 IPC，批量插入需自己拼多值 `INSERT` | **选它** |
| `better-sqlite3` + 自定义 command | 同步、事务方便 | 要写 Rust command、要处理 ABI、打包要带 native 模块 | 不选 |
| `rusqlite` + 自定义 command | 性能最好 | 业务逻辑会被诱到 Rust 里 | 不选 |

**性能预算**（1 万词条、单用户）：

| 操作 | 目标 |
|---|---|
| 首页加载（含统计） | < 150 ms |
| 生成会话（取 150 条） | < 50 ms |
| 单卡结算（1 次 UPDATE + 1 次 INSERT） | < 10 ms |
| 录入 50 行 | < 300 ms |

一期不需要担心性能。**批量录入必须用单条多值 `INSERT`**，不要循环 50 次 IPC——这是唯一容易踩的坑。

## 8. 数据模型

### 8.1 迁移策略

- 用 `tauri-plugin-sql` 的 `Migration`，**每个版本一个文件**：`src-tauri/migrations/0001_init.sql`
- **版本只增不改**：已发布的迁移文件永远不回头改
- 迁移在应用启动时自动执行，失败要**拦住启动并显示错误**，不要静默继续（半个 schema 比崩掉更危险）
- 每次改 schema 的流程：写新 `000N_*.sql` → 升 `Cargo.toml` 里 `version` → 写迁移测试

### 8.2 DDL（`0001_init.sql`）

> **不要在这份 SQL 里写 `PRAGMA`**。`journal_mode` 是数据库持久属性、`foreign_keys` 是**每连接**属性，两者都必须在每次建立连接后单独执行（见 §8.5）。放进迁移里既会被 sqlx 当成「返回行的语句」处理，也管不到后续连接。

```sql
-- ---------- 设置 ----------
CREATE TABLE settings (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);

-- ---------- 词条 ----------
CREATE TABLE words (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  headword            TEXT    NOT NULL,           -- 展示形式，保留你输入的大小写
  norm                TEXT    NOT NULL UNIQUE,    -- 归一化键，唯一
  phonetic            TEXT,                       -- 音标（可空，AI 或手工补）
  source              TEXT,                       -- 标签：zhuanshengben/cet4/cet6/manual（v1 仅展示，不参与调度）
  note                TEXT,                       -- 辨析/词根（可选保存）
  example_json        TEXT,                       -- 例句 JSON（AI 生成，可选）

  status              TEXT    NOT NULL DEFAULT 'learning',  -- learning|graduated|suspended

  -- ts-fsrs 记忆状态（与 Card 字段一一对应）
  fsrs_state          INTEGER NOT NULL DEFAULT 0,           -- 0 New 1 Learning 2 Review 3 Relearning
  fsrs_due            INTEGER,                              -- epoch ms
  fsrs_due_day        TEXT,                                 -- YYYY-MM-DD（按 day_boundary_hour 算）
  fsrs_stability      REAL    NOT NULL DEFAULT 0,
  fsrs_difficulty     REAL    NOT NULL DEFAULT 0,
  fsrs_reps           INTEGER NOT NULL DEFAULT 0,
  fsrs_lapses         INTEGER NOT NULL DEFAULT 0,
  fsrs_scheduled_days INTEGER NOT NULL DEFAULT 0,
  fsrs_last_review    INTEGER,                              -- epoch ms

  created_at          INTEGER NOT NULL,
  updated_at          INTEGER NOT NULL
);

CREATE INDEX idx_words_due    ON words(status, fsrs_due_day);
CREATE INDEX idx_words_norm   ON words(norm);
CREATE INDEX idx_words_status ON words(status);

-- ---------- 义项 ----------
CREATE TABLE senses (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  word_id    INTEGER NOT NULL REFERENCES words(id) ON DELETE CASCADE,
  meaning_cn TEXT    NOT NULL,
  layer      INTEGER NOT NULL DEFAULT 1,        -- 1 = 当初录入  2 = 事后补充
  origin     TEXT    NOT NULL DEFAULT 'manual', -- manual|ai
  sort       INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_senses_word ON senses(word_id, layer, sort);

-- ---------- 复习日志（即使不记对错，也必须记时间） ----------
CREATE TABLE review_logs (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  word_id          INTEGER NOT NULL REFERENCES words(id) ON DELETE CASCADE,
  rating           INTEGER NOT NULL,   -- 1 Again / 3 Good
  state_before     INTEGER NOT NULL,
  state_after      INTEGER NOT NULL,
  due_after        INTEGER,
  stability_after  REAL,
  difficulty_after REAL,
  elapsed_days     INTEGER,
  reviewed_at      INTEGER NOT NULL,
  session_id       TEXT
);

CREATE INDEX idx_logs_word ON review_logs(word_id, reviewed_at);
CREATE INDEX idx_logs_time ON review_logs(reviewed_at);

-- ---------- 会话 ----------
CREATE TABLE sessions (
  id         TEXT PRIMARY KEY,     -- uuid
  started_at INTEGER NOT NULL,
  ended_at   INTEGER,
  planned    INTEGER NOT NULL,     -- 本次排入
  shown      INTEGER NOT NULL DEFAULT 0,
  again      INTEGER NOT NULL DEFAULT 0,
  deferred   INTEGER NOT NULL DEFAULT 0
);

-- ---------- 元信息 ----------
CREATE TABLE meta (
  key   TEXT PRIMARY KEY,
  value TEXT
);
INSERT INTO meta(key, value) VALUES ('schema_version', '1');
```

### 8.3 为什么 `review_logs` 必须记（即使你从不按「不会」）

1. **即使不记对错，也要记时间**：万一以后你想开「不会」按钮，或想从 Good-only 迁移到带反馈的调度，历史时序是唯一能重建记忆状态的东西
2. **`ts-fsrs` 提供 `reschedule()`**：它正是靠 `FSRSHistory[]` 重放历史来重算。没有日志，这个能力永远用不上
3. 排查「为什么这个词一直不出现」时，日志是唯一证据

### 8.4 事务与备份一致性

- 单卡结算 = 1 次 `UPDATE words` + 1 次 `INSERT review_logs` + 1 次 `UPDATE sessions`。**必须包在一个事务里**
- `plugin-sql` 的事务接口较薄，做法：`BEGIN` → 语句 → `COMMIT`，失败 `ROLLBACK`；封装在 `data/sqlite/tx.ts`，**业务层不手写 `BEGIN`**
- WAL 模式下导出前执行 `PRAGMA wal_checkpoint(TRUNCATE)`，保证 `.db` 单文件自洽

### 8.5 连接期 PRAGMA（**每次建连接都要设，不能放迁移里**）

`tauri-plugin-sql` 底层用 sqlx 的连接池。`PRAGMA foreign_keys` 是**每连接**生效的，放进迁移文件只会影响迁移那一瞬间的连接，之后所有连接默认都是 `OFF`——**外键形同虚设**。

```ts
// src/data/sqlite/db.ts
let dbPromise: Promise<Database> | null = null

export function getDb(): Promise<Database> {
  if (!dbPromise) {
    dbPromise = (async () => {
      const db = await Database.load('sqlite:wordpacer.db')
      await db.execute('PRAGMA journal_mode = WAL')      // 持久属性，设一次即可，重复执行无害
      await db.execute('PRAGMA foreign_keys = ON')       // 每连接属性，必须在同一连接上生效
      await db.execute('PRAGMA busy_timeout = 5000')     // 防瞬时锁冲突直接报错
      return db
    })()
  }
  return dbPromise
}
```

> **风险提示**：`plugin-sql` 的连接池会开多个连接，而 `Database.load()` 只有一个句柄。如果实测发现 `foreign_keys` 在部分查询里未生效（例如 `ON DELETE CASCADE` 没触发），方案是：**不依赖数据库级外键**，把级联删除写在应用层（`data/sqlite/repo.ts` 里删词条时先删 `senses` 和 `review_logs`）。**M0 就要验证这一点**，不要等到 M4。

| R9 | AI 补义项「提前泄题」 | 回忆强度被破坏 | L2 义项 `reps >= 3` 才显示（§4.3.3） |
| R10 | Tauri 首次构建慢 / 杀软误报 | 影响体验 | 文档写明首次构建 5–15 分钟；发布时在 README 提一句未签名可能触发 SmartScreen |
| R11 | `maximum_interval=50` 让「自适应」在 3 次复习后被削平 | 间隔固定在 50 天，外行看像固定间隔算法 | **这是为备考做的刻意取舍**（§5.6.1）；考完试把上限调到 365 即恢复长间隔能力 |

**R1 的备选方案（如果 Rust 环境真搞不定）**：本项目从设计上把业务逻辑 100% 放在 TS、数据库访问收敛在 `Repo` 接口后。换 Electron 只需替换外壳与一个 `Repo` 实现：

- `plugin-sql` → `better-sqlite3`，接口不变
- `dialog/fs` 插件 → Node `fs`
- UI、`domain/`、测试**一行不改**

这就是分层的实际价值，不是架构洁癖。

## 14. 开放问题（v1 不阻塞，记录备查）

1. **词表来源**：v1 已定「无内置词表、纯手打录入、单一词库」。如果以后词量涨到几千、手打不现实，再考虑「批量粘贴/CSV 导入」——但那属于新需求，不在 v1 范围。
2. **「不会」按钮默认关闭是否合理**：如果在 M2 试用两周后你几乎不开，考虑直接删掉这个功能，把设置项减到一个
3. **同一次会话内 Again 的词是否本轮再出现**：v1 不出现（复习即完成）。若你觉得该再考一次，加开关
4. **发音**：TTS（Web Speech API，零成本）还是打包音频？前者简单，但 Windows 上的英文音色质量一般
5. **多设备**：不打算做。若要，最小方案是「导出 JSON → 手动同步」，不做自动

## 15. 附：v1 决策一览（便于核对）

| 维度 | 决策 |
|---|---|
| 形态 | Windows 独立桌面应用（Tauri v2），单机本地 |
| 存储 | SQLite，单文件，`plugin-sql` + 迁移 |
| 排程 | `ts-fsrs` 5.4.2，`request_retention=0.85`，`maximum_interval=50`，`enable_short_term=false`，`enable_fuzz=false` |
| 评分 | 二元：默认 Good，可选 Again（默认关闭按钮） |
| 会话 | 上限 150 可调，逾期优先，超出顺延，可「一次性看完」 |
| 逾期处理 | 不做手工分档，交给 FSRS 按实际经过天数重算 |
| 间隔上限 | **50 天**，按「考前还能再见一次」倒推（§5.6.1）。考完试可调到 365 |
| 毕业 | `state=Review && scheduled_days>=90 && reps>=4` 或 `lapses>=6`；备考期内不会触发自然毕业 |
| 词库 | **单一词库，完全由自己录入；无内置词表、无分层**。`source` 仅作标签，不参与任何计算 |
| 录入 | 纯手打，行式批量粘贴，两步（预览→导入） |
| 归一化 | 大小写/空白/标点；**不做词形还原**，改疑似重复提示 |
| 义项 | L1（当初）/ L2（事后，含 AI），L2 在 `reps >= 3` 后显示 |
| AI | 录入时校对英文拼写（只提示、不改、不发释义）；默认关闭；绝不进回忆屏 |
| 复习 UI | 单卡翻页，只显英文，点一下出中文 |
| 不做 | 打卡、每日配额、日历主界面、桌宠、云同步、成绩预测、词库分层 |
| 开源 | MIT，纯本地无遥测，数据/密钥/导出文件不入库 |
